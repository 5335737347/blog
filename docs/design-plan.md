# 前端设计方案（v1）

状态：**已实施并通过验收（阶段一至四）**。视觉与交互方案见下文；
落地情况与偏差记录在文末「实施记录」。

Last checkpoint: 2026-09-17 首次方案（对标 26 个同类站点，其中 22 个完成真实渲染分析）

## 1. 定位与设计目标

本站定位是**一个 CS 学生的二次元技术博客**：内容上是技术实践与学习记录，气质上偏二次元、轻松、有个人色彩。

设计目标按优先级排序：

1. **长文阅读体验优先**。文章页才是产品本身，其它页面都为它服务。
2. **一眼记住，久看不累**。首页可以沉浸、可以有壁纸和氛围；内页必须安静、克制、可长时间阅读。
3. **气质统一，但不靠装饰堆叠**。二次元气质来自配色、壁纸、文案与细节，不来自满屏玻璃卡片和渐变文字。
4. **可长期演进**。所有视觉决策落到设计令牌上，后续调整只改令牌与模板，不做逐页救火。

## 3. 同类站点调研（真实渲染）

对 26 个站点做了无头浏览器渲染分析：22 个成功，4 个因网络/超时失败（`astro-koharu.vercel.app`、`notev.com`、`linlily.com`、`fuwari.vercel.app`）。样本分五组：同定位二次元博客（10）、二次元主题（2）、开发者博客（3）、设计型开发者博客（4）、中文技术博客（2）。

### 3.1 三个可复用的规律

**规律一：高质量站点只走两条路，中间态最差。**

| 路线 | 代表 | 度量（桌面） | 特征 |
|---|---|---|---|
| 内容极简 | `yumoe.com` 0 模糊背景 / 0 渐变 / 1 张背景图；`rauno.me` 135 元素；`paco.me` 96 元素；`leerob.com` 98 元素 | 元素数 96–140 | 只有字体、留白、封面图；靠字号阶梯和网格取胜 |
| 沉浸装饰 | `shoka` 36 处渐变背景 / 21 处阴影；`imydl` 19 张背景图；`ichika` 4557 元素 | 元素数 400–4500 | 壁纸、动效、图标体系全套上；装饰是主角 |

而“中低装饰 + 高饱和渐变文字 + 玻璃卡片”的组合，在这批样本里恰恰是**质量最低**的一档——装饰不足以成为风格，又足以干扰阅读。

**规律二：文章的阅读质感由排版参数决定，与装饰无关。**

深度测量结果（正文容器宽 / 正文字号 / 行高）：

| 站点 | 正文列宽 | 正文字号 | 行高 | H1 | H2 | 备注 |
|---|---|---|---|---|---|---|
| 张洪Heo | 950px | 17px | 28.9px(1.7) | 42px/1.38 | 26px，上边距 30px | 有目录、有阅读进度、封面图 + 标题压图 |
| ShokaX 文档 | 720px | 16px | 28px(1.75) | 42px/1.2 | 35px | 三栏布局，右侧附加信息栏 |
| Josh Comeau | 实测列居中 | 18px | 27px(1.5) | 36px | 32px，上边距 48px，标题带锚点 | 目录做成正文首块，侧栏为交互演示 |

共同点：**正文列宽 720–950px、字号 16–18px、行高 1.5–1.75、H2 有明显上边距并有锚点**。三点都满足，读起来就“高级”。

**规律三：中后台式的信息页（列表/归档）靠卡片一致性，不靠花活。**

`zhheo` 首页是 2 列大图卡片网格，1859 个元素里 62 处阴影、10 处渐变，但每张卡片结构完全一致：封面图 + 标题 + 作者/评论数/阅读数 + 日期。`innei` 是极宽留白的单列时间线 + 右侧“碎念/来信”窄栏。两者都靠**同一套卡片结构 + 稳定栅格 + 优质封面图**。

**一个值得注意的发现：中文长文用衬线体是高质量站点的常见选择。** `小浠の小窝`（Noto Serif SC 18px/1.65）、`Innei`（Noto Serif SC 正文 + Instrument Sans 界面）、`yumoe`（Droid Serif）、`leerob`（Iowan Old Style）都用衬线正文。衬线体在中文长文里能显著提升“阅读感”，且同字号下视觉更小、更耐读。本方案默认先用无衬线（PingFang SC）保证一致性与加载零成本，把“正文衬线化”列为可选实验项（见第 13 节）。

最终可复用结论：

- **背景用中性色阶（白 / 极浅灰 / 暖白），不用彩色渐变铺满**；
- **正文色用中性深灰，不用品牌色**；
- **圆角主体在 4–12px，胶囊圆角只给标签和头像**；
- **常用容器宽 1200px（范围 1080–1300），阅读列宽 720px（范围 650–950）**。

## 4. 设计方向定案

一句话：**一个站，两张脸——首页沉浸、内页极简；粉蓝双色只做点缀，中性色阶承担骨架。**

具体主张：

1. **沉浸只留在首页首屏**。壁纸、氛围光、轮换动画、渐变文字**仅允许出现在首页 hero**，其余页面一律纯色背景。
2. **配色保持粉蓝双色体系**，沿用线上 `#ef5f7a` / `#4da9e8`（比本地代码的 `#f472b6` 更暖、更偏二次元，且作为按钮底色对比度更好）。紫色只保留在首页 hero 的装饰渐变里。
3. **粉色占屏比例 ≤ 5%**：只用于主按钮、当前导航项、hover 态、进度条。
4. **中性色阶做骨架**：三段背景、四级文字、两组边框，全部走令牌。
5. **中文字体优先**：正文栈以 PingFang SC / 微软雅黑起头，界面数字与代码用 Geist + 等宽栈。
6. **emoji 全部替换为线性 SVG 图标**（保留极少数文案性 emoji）。
7. **文章页从「带装饰的文章」升级为「阅读器」**：720px 正文列 + 左侧粘性目录 + 右侧操作栏。

## 5. 设计令牌（核心交付物）

所有值以 CSS 变量定义在 `apps/web/src/app/globals.css`，并通过 `@theme inline` 暴露给 Tailwind，**页面里禁止再写死颜色**。

### 5.1 颜色

```css
:root {
  /* 骨架：中性色阶 */
  --bg:            #ffffff;   /* 页面底 */
  --bg-subtle:     #f7f9fc;   /* 区块交替底 */
  --surface:       #ffffff;   /* 卡片 */
  --surface-hover: #f4f7fb;
  --border:        #e3e9f2;
  --border-strong: #cfd9e6;

  /* 文字：四级 */
  --text:    #1f2a3c;  /* 标题、正文 */
  --text-2:  #46566e;  /* 次级正文、摘要 */
  --text-3:  #6b7c94;  /* 元信息、日期、标签 */
  --text-4:  #9aa9be;  /* 极弱提示，仅限大字号或非必要信息 */

  /* 强调：粉（行动）+ 蓝（信息） */
  --primary:      #ef5f7a;  /* 主按钮底色、当前项、进度条 */
  --primary-deep: #d4455f;  /* 粉色的可读文本变体 */
  --primary-soft: #fff1f4;  /* 粉色浅底 */
  --accent:       #4da9e8;  /* 链接、信息、focus ring */
  --accent-deep:  #2b7fb8;  /* 蓝色可读文本变体 */
  --accent-soft:  #eef7fe;  /* 蓝色浅底 */

  /* 状态色：每个只允许一种用法 */
  --success: #2f9e6b;  --warning: #c98a15;  --danger: #d84a4a;

  /* 专属令牌 */
  --shadow-sm: 0 1px 2px rgba(24, 39, 66, .06);

  --bg-subtle:     #141b2a;
  --surface:       #18202f;
  --surface-hover: #1f2939;

```

使用规则：

- 正文文字只用 `--text` / `--text-2`；**品牌色永远不做正文色**。
- 需要粉色文字时用 `--primary-deep`（白底约 4.9:1，达 AA）。
- 链接默认继承文字色 + 下划线；需要颜色时用 `--accent-deep`。
- 焦点环统一 `--ring`，不再用 `outline: 2px solid var(--primary)`。
- 暗色模式保持和亮色一致的层级关系，只是明度反转。

### 5.2 字体与排版阶梯

```css
--font-sans: "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei", "Hiragino Sans GB",
             ui-sans-serif, system-ui, -apple-system, "Segoe UI", sans-serif;
--font-mono: "Geist Mono", ui-monospace, SFMono-Regular, Menlo, Consolas, monospace;
```

| 层级 | 字号 | 行高 | 字重 | 用途 |
|---|---|---|---|---|
| `hero` | 56px / 移动 32px | 1.15 | 700 | 首页站名 |
| `h1` | 36px / 移动 28px | 1.25 | 700 | 文章标题、页面标题 |
| `h2` | 26px | 1.4 | 650 | 正文一级小节 |
| `h3` | 21px | 1.45 | 600 | 正文二级小节、卡片组标题 |
| `body-lg` | 17px | 1.75 | 400 | **文章正文** |
| `body` | 16px | 1.7 | 400 | 摘要、列表正文 |
| `ui` | 15px | 1.5 | 500 | 导航、按钮、表单 |
| `meta` | 13px | 1.5 | 400 | 日期、阅读时长、标签 |
| `micro` | 12px | 1.4 | 500 | 上标、角标、键盘提示 |

硬规则：

- **正文行高 ≥ 1.7，字间距 `letter-spacing: 0.01em`**（中文长文的关键参数）。
- 正文列宽 `max-width: 720px`，移动端 `padding-inline: 20px`。
- 界面文字**不得小于 13px**；12px 只允许出现在角标/Kbd 这类非正文元素。
- 不使用 webfont 加载中文字体（体积不可接受）；只加载 Geist Mono（拉丁子集）。
- 数字与日期统一 `font-variant-numeric: tabular-nums`。

### 5.3 间距、圆角、阴影、边框

```css
/* 间距：4px 基准 */

--space-12: 48px; --space-16: 64px; --space-20: 80px; --space-24: 96px;

/* 圆角：四档，不再出现 rounded-xl/2xl/3xl 混用 */
--radius-xs: 6px;    /* 标签、角标、Inline code */
--radius-sm: 10px;   /* 按钮、输入框 */
--radius-md: 14px;   /* 卡片、图片、代码块 */
--radius-lg: 20px;   /* 大面板、移动端抽屉 */
--radius-full: 999px; /* 仅头像与胶囊标签 */
```

- 边框一律 `1px solid var(--border)`；**禁止半透明白边** `rgba(255,255,255,.85)`。
- 阴影只有 `--shadow-sm`（卡片默认）与 `--shadow-md`（hover、浮层）；**取消彩色阴影**。
- 悬浮效果从 `translateY(-2px)` 改为仅颜色/边框变化，避免列表抖动。

### 5.4 栅格与断点

| 断点 | 宽度 | 布局 |
|---|---|---|
| `sm` | ≥640px | 单列 + 正常间距 |
| `md` | ≥768px | 卡片双列；导航由头部菜单承担（底部标签栏已于 2026-09-17 移除） |
| `lg` | ≥1024px | 侧栏出现（列表页） |
| `xl` | ≥1280px | 文章页三栏（目录 / 正文 / 操作栏） |

- 内容容器统一 `--container: 1200px`（替代现在的 1408px）；阅读容器 720px。
- 侧栏固定 260px，间距 40px。

## 6. 页面结构方案

### 6.1 首页（沉浸 + 落地）

保留现有“整屏壁纸轮换”的设定，但把首屏变成一个**有出口的落地页**：

```text
┌─ Hero（100svh，壁纸 + 轻遮罩）──────────────┐
│  站名（hero 56px，白字 + 轻投影）           │
│  一句话简介（16px，最大 2 行）              │
│  搜索框（玻璃胶囊，居中，主 CTA）           │
│  ↓ 轻微下滚提示（可选）                     │
├─ 最新文章（白底）──────────────────────────┤
│  区块标题 + “全部文章 →”                    │
│  三栏卡片栅格（xl 三列 / md 两列 / 移动单列）│
│  文章卡片 × 6                               │
├─ 最近在做（bg-subtle 交替底）───────────────┤
│  近况摘要卡（读 Profile.now）+ 前往 /now    │
├─ 分类与标签（白底，两栏）───────────────────┤
│  分类列表（名称 + 篇数）│ 标签云（top 20）    │
└─ Footer ────────────────────────────────────┘
```

要点：

- **搜索从 hero 正中移出视觉噪音区**，做成单行玻璃胶囊，成为首屏唯一交互焦点。
- 遮罩用 `--hero-scrim`，保证任何壁纸下白字都可读。
- 首屏**不再出现 Cookie 提示卡与浮动按钮遮挡主体**：Cookie 提示改为贴底窄条，2 秒后自动淡出，或延后到首次滚动后出现。
- 卡片造型统一：`--radius-md` + `--border` + `--shadow-sm`；封面比例固定 `16/9`；无封面时回落为**渐变色块 + 站点图标**（保证栅格不塌）。
- 卡片信息层级：分类（accent-soft 胶囊）→ 标题（17px/600，最多 2 行）→ 摘要（15px/`--text-3`，最多 2 行）→ 元信息行（日期 · 阅读时长 · 标签 ≤2 + “+n”）。
- 分类区改为**带描述与计数的列表**（比一排胶囊更易读）。

### 6.2 文章页（核心）

从「一栏带装饰」升级为「三栏阅读器」：

```text
┌─ 顶部：阅读进度条（2px，--primary）───────────────────────┐
│  面包屑 / 分类 · 发布日期 · 阅读时长 · 字数                 │
│  H1（36px/1.25，max-width 720px）                         │
│  导语（excerpt，17px，--text-2）                           │
│  封面图（16/9，--radius-md，可点击放大）                    │
├──────────┬──────────────────────────────┬────────────────┤
│ 目录      │  正文（720px）                │  操作栏 44px    │
│ 粘性      │  H2/H3 + 锚点                 │  ♡ 点赞         │
│ 240px    │  段落 17px/1.75               │  ↗ 分享         │
│ 当前项高亮│  代码块（语言标签 + 复制）      │  ☰ 目录(移动)   │
│ 滚动联动  │  图片（图注 + 放大）           │  ↑ 回到顶部     │
├──────────┴──────────────────────────────┴────────────────┤
│  上/下一篇（两栏）→ 相关文章（2 列）→ 版权声明 → 评论       │
└──────────────────────────────────────────────────────────┘
```

**目录改造（当前最大的结构问题）**：现有 `TableOfContents` 直接插在标题区与正文之间，长文时会先看到一屏目录。新方案：

- 桌面：移到正文左侧粘性栏，`IntersectionObserver` 高亮当前小节，超过 30 项时内部滚动。
- 移动：收进右下角浮动按钮打开的底部抽屉。
- 标题锚点：hover 显示 `#`，点击写入 URL hash（现有 `.markdown-content` 的写法保留，改为 `--text-4` 色）。

**正文排版规则**：

| 元素 | 规格 |
|---|---|
| 段落 | 17px / 1.75 / `--text`，段间距 1.25em，左对齐（不用两端对齐 + 连字符） |
| H2 | 26px / 650，上边距 48px、下边距 16px，左侧 3px `--primary-soft` 竖线修饰 |
| H3 | 21px / 600，上边距 32px |
| 链接 | `--text` + `text-decoration: underline; text-underline-offset: 3px;` hover 转 `--primary-deep` |
| 行内代码 | `--bg-subtle` 底 + `--radius-xs` + 等宽 0.9em + `--primary-deep` 文字 |
| 代码块 | 深色底 `#16131f`（暗色下 `#0d1016`）+ `--radius-md`；顶部 40px 栏放语言标签与复制按钮；`overflow-x: auto`；支持行号（可选） |
| 引用 | 左 3px `--accent` + `--accent-soft` 底 + `--radius-sm`，字号 16px |
| 表格 | 全宽可横向滚动，表头 `--bg-subtle`，行分隔 `--border` |
| 图片 | `--radius-md` + 居中 + 图注 13px `--text-3`；点击进入 lightbox（点遮罩/ESC 关闭） |
| 列表 | 项目符号用 `--primary`，嵌套缩进 1.5em |
| 数学公式 | KaTeX 保持现状，居中块与 `--bg-subtle` 底 |
| 提示块 | 新增 `:::tip/warning/danger` 三类，底色用 soft 令牌 + 左侧 3px 竖线 |

**文章尾部**：上/下一篇（左右两栏，hover 只变边框色）→ 相关文章 2 列 → 版权声明（CC BY-NC-SA + 原文链接，仅在允许时展示）→ 评论。

### 6.3 列表 / 归档 / 标签 / 分类

四类页面共用一套列表骨架，只换数据整形方式：

| 页面 | 布局 |
|---|---|

| `/archive` | 按年份分组的时间线；年份粘性小标题（20px/650），每条为 `日期 ｜ 标题`；移动端只保留年月 |
| `/tags/[tag]` | 顶部标签说明 + 计数 + 相关标签行 + 文章列表（复用列表视图） |
| `/categories/[category]` | 分类名 + 描述 + 计数 + 文章卡片栅格 |

## 7. 动效规范

| 场景 | 时长 | 缓动 | 说明 |
|---|---|---|---|
| 颜色/边框变化 | 120ms | `ease-out` | 链接、按钮、导航 |
| 浮层、抽屉 | 200ms | `cubic-bezier(.2,.8,.2,1)` | 目录抽屉、lightbox、移动导航 |
| 首页壁纸切换 | 800ms | `ease-out` | 仅 hero 内部，`opacity` + 轻微 `scale(1.01)` |
| 内页入场动画 | — | — | **取消**，只保留 hero 内的 `fade-in-up` |
| 滚动动效 | — | — | 不使用 AOS 类滚动触发动画 |

- 全部动效遵守 `prefers-reduced-motion: reduce`（现有实现保留了这段，继续保留）。
- 不做页面级路由过渡动画，避免返回时闪烁。
- 壁纸轮换继续沿用当前的“按时间戳对齐、5 分钟一换”实现（多标签页同步），不改成随机或定时器递增。

### 实施中发现的真实缺陷（已修）

1. **`rehype-highlight` 的语言配置无效**：`MarkdownContent` 传的是字符串数组，而该选项要求 lowlight 语法对象，导致服务端报 `languageDefinition.bind is not a function`、**全站代码高亮静默失效**。改为传入 `lowlight` 的 `common` 语法集合。测试期间未发现，因为此前没有针对正文渲染的断言。
2. **`/api/publish` 的分类解析会 500**：`resolveCategory` 用 slug 做 upsert 却写入中文 name，当分类已按中文名存在（如 `{name:"技术", slug:"tech"}`）时撞 `Category.name` 唯一约束。改为先按 slug、再按 name 查找，最后才创建；新增回归测试 `publishMarkdown reuses an existing category whose name and slug do not correspond`。
3. **Tailwind `@theme inline` 覆盖默认字号**：自定义 `--text-h1/h2/h3/hero/body-lg` 会遮蔽 `text-sm`/`text-3xl` 等标准类的解析路径，实际只保留 12/13/15px 三档，页面标题字号静默回退。已删除自定义字号阶梯，只用 Tailwind 默认阶梯 + `text-ui/meta/micro` 三档补足（13px 为界面文字下限，12px 仅用于 Kbd）。
4. **`ShareActions` 重复声明 `share`**：导致文章页 500；`tsc --noEmit` 与构建均能通过，只有运行时编译报错，说明构建验证不能替代一次真实渲染检查。
5. **两处无障碍缺陷（axe-core 实测发现）**：24 个「+N」角标用了 `--text-4`（对白底仅 3.5:1）；长代码块的横向滚动区不可键盘聚焦。前者改为 `--text-3` 并把 `--text-4` 明确限定为「非文字用途」，后者给 `pre` 加 `tabIndex={0}` 与 `aria-label`。
6. **打印样式失效**：隐藏规则写成 `[class*="CommentForm"]` 这类类名子串匹配，而组件的 `className` 里根本没有组件名，规则从未命中；同时 `max-width` 限制让相关文章卡片在纸上压成一字一行。改为显式 `data-print="hide"` / `data-print="cover"` 标注，并放开打印时容器宽度、栅格改单栏、相关文章与评论区不打印。

### 与方案的偏差

- **Cookie 提示**：从居中卡片改为贴底窄条（`bottom-14 lg:bottom-0`），避免遮挡 hero 搜索框与文章封面，也不与移动端标签栏重叠；移动端使用更短文案。
- **首页 hero 排版**：站名由居中改为左对齐（同类站点中沉浸式与内容式混合的首屏几乎都是左对齐），并加顶部渐变压暗保证浅色壁纸下站名与导航可读。
- **分类去色**：`hashTagColor` 被删除，标签改为中性样式、hover 才上强调色；分类胶囊固定用蓝色系（`accent-soft`）。
- **新增说明**：`/tags` 索引路由不存在，页脚导航未加入该入口（此前链接会 404）。

### 稳定性收尾（2026-09-17，本地）

视觉改版后做了一轮功能与链路排查，修掉 3 个真实缺陷：

1. **音乐播放器面板打不开**：重写 `Header` 时漏掉了 `<LazyMusicPlayer />`，按钮只切换图标与 `aria-expanded`，面板永远不会渲染。已补回，并保留定位所需的 `relative` 容器。
2. **编辑文章会改掉 slug**：`updateArticle` 用 `slugify(slugInput || title || existing.title)`，于是「只改正文」也会按标题重算 URL，断掉已发布文章的链接与外链。改为只在显式传入 slug 时变更，并新增回归测试。
3. **登录后头部仍显示「注册 / 登录」**：`AuthNav` 只在挂载时读一次会话，而登录走客户端跳转、组件不会重新挂载，必须硬刷新才更新。改为可订阅的会话外部存储（`useSyncExternalStore`），登录、登出、路由变化都会同步。

同时删除了两个完全无人引用的死代码组件：`EffectsToggle` 与 `FallingEffects`（含 4 个 emoji 特效选项），公开面因此不再有任何 emoji 充当图标。

**新增可重复执行的浏览器冒烟检查：`npm run smoke`。**

- 自建临时数据库（`apps/api/scripts/smoke-seed.mjs` 只写入 1 篇文章/1 个分类/1 个标签）、独立端口的 API 与 Web 实例、独立构建目录（Next 16 不允许同目录两个 dev server 共用 `.next`），跑完自动清理。
- 检查内容：11 个页面可渲染且无控制台报错与失败请求；首页内部链接可达；关键组件（音乐/主题入口）确实渲染；首页与文章页渲染的是真实数据（正文/目录/代码块）。

- `npm run smoke:prod` 对生产构建（`next build` + `next start`）跑同一套检查，发布前使用。
- **冒烟自带数据库自检**：API 启动时在 stderr 打印实际使用的数据库文件，脚本核对它就是本次创建的临时库。没有这道自检时，冒烟可能在开发库上运行，而「首页渲染出文章」这类断言会因为开发库恰好有数据而**假通过**——这个风险是在检查 `smoke:prod` 的失败输出时才意识到的。
