# 注册验证、消息投递与防刷

本文说明注册验证码的当前实现、外部服务准备状态、目标接入边界和上线验收要求。
环境变量以[环境变量](environment.md)为准，HTTP 请求与响应以
[OpenAPI](openapi.yaml)为准，尚未完成的工作以[后续计划](next-plan.md)为准。

## 状态定义

本文使用以下术语，避免把外部控制台配置误写成已经上线：

| 状态 | 含义 |
|---|---|
| 已准备 | 服务商账号、域名或受限凭据已经由所有者在仓库外准备 |
| 已实现 | API 已包含适配器、配置校验、错误处理和自动化测试 |
| 已部署 | 真实服务器已安全配置并运行该实现 |
| 已验收 | 已完成真实投递、防刷、失败路径、告警和费用控制检查 |

只有同时达到“已部署”和“已验收”的渠道，才可以在生产注册页面开放。服务商控制台显示
域名已验证，不等于项目已经实现或部署该渠道。

## 当前代码行为

Fastify API 拥有验证码生成、投递、持久化、验证和限流逻辑，Web 只展示 API 声明为可用的
注册方式。

| 项目 | 当前行为 |
|---|---|
| 验证渠道 | 仅 `email`（手机号通道已于 2026-08 移除） |
| 验证码 | 6 位数字，10 分钟有效 |
| 错误尝试 | 最多 5 次，超过后删除验证码 |
| 发送限流 | 每个直接客户端 IP 每小时 5 次；每个规范化目标每小时 5 次 |
| 注册限流 | 每个直接客户端 IP 每小时 5 次 |
| 登录限流 | 每个直接客户端 IP 每 15 分钟 20 次；**每个账号每 15 分钟 10 次失败** |
| 重置密码 | 邮箱验证码（与注册同一套机制，用途前缀不同，互不通用） |
| 重置限流 | 发码：每个 IP 与每个目标各 5 次/小时；提交：每个 IP 10 次/小时 |
| 改密 | 需当前密码 + 有效会话；成功后吊销该账号全部令牌，并为当前设备补发一张 |
| 邮箱投递 | 当前仅实现 SMTP |
| 生产可见性 | 仅在 SMTP 投递配置完整时声明邮箱通道可用 |
| 开发回退 | 需显式设置 `ALLOW_DEBUG_VERIFICATION_CODE=true`；生产环境禁止该回退 |
| SMTP 传输 | 未加密连接上拒绝发送凭据，除非显式设置 `SMTP_ALLOW_INSECURE=true` |

邮件地址在验证码目标和限流键中统一为小写。目标限流键使用摘要，不能通过大小写变化创建新桶。

**账号枚举防护**：`POST /api/auth/password/reset-code` 对「已注册」与「未注册」的邮箱返回
完全相同的响应，且都会真正走一次发送流程（受同样的限流约束），因此无法通过响应或耗时
差异判断某个邮箱在本站是否有账号。重置提交时，未注册邮箱与验证码错误返回同一个结果。

验证码按用途加了前缀（`register:` / `reset:`），所以注册验证码不能被拿去重置密码，
两者也不会互相覆盖。

登录的账号维度限流**只统计失败次数**，且成功登录会清零计数。这样既能阻挡换 IP 的撞库，
又不会因为正常用户输错密码、或攻击者故意输错而把某个账号锁死。
账号限流键同样使用摘要，限流表中不保存用户名或邮箱明文。

`sent: true` 只表示上游服务接受了发送请求，不表示邮件已进入收件箱。
真实投递仍须通过服务商事件或测试收件箱验收。

## 外部服务准备状态

### 邮件

- 事务邮件服务商选用 Resend；无法登录的新 SendGrid 账号不再作为项目依赖。
- 项目发信域名已完成 DKIM、SPF、专用 return-path MX 和 DMARC 验证。
- Resend 受限发信 Key 已由所有者保存在仓库外；上线时以 `RESEND_API_KEY` 写入服务器环境。
- 邮件模板由项目代码管理，不使用服务商托管模板。
- Resend **同时提供 HTTP API 与 SMTP 接入**，且两条路径的凭据校验相互独立。
  2026-09-21 生产实测：同一把 Key 走 HTTPS API 能正常发信，走 SMTP 中继却被
  AUTH 535 拒绝。因此当前实现的传输适配器是 **HTTP API，优先于 SMTP**：

  ```bash
  RESEND_API_KEY="re_..."           # 优先；配了它就不走 SMTP
  RESEND_FROM="noreply@kpblog.cc"   # 发件域名须已在 Resend 完成验证；留空回退 SMTP_FROM
  ```

  SMTP 保留为回退路径（仅 `RESEND_API_KEY` 为空时启用），配置方式不变：

  ```bash
  SMTP_HOST="smtp.resend.com"
  SMTP_PORT="465"          # 隐式 TLS；587 为 STARTTLS
  SMTP_SECURE="true"
  SMTP_USER="resend"       # Resend 规定为字面量，不是邮箱
  SMTP_PASSWORD="..."      # SMTP 凭据；不要填 HTTP API Key（会被 AUTH 535 拒绝）
  SMTP_FROM="noreply@kpblog.cc"   # 必填：USER 不是邮箱，留空会导致 MAIL FROM:<resend>
  ```

- HTTP 路径用 `/api/auth/verification-code` 向 `delivered@resend.dev`（Resend 官方
  测试收件地址）真发一封验证码，返回 200 即为投递链路打通；SMTP 回退路径用
  `npm run smtp:check` 逐级探测（配置 → 连接 → 能力 → 传输安全 → 认证 → 发件人），
  停在失败的那一步并给出可执行的原因，加 `-- --send you@example.com` 会真发一封测试邮件。

### 手机号验证码（已移除）

- 手机号验证码通道（SMS 网关、区号选择、E.164 规范化）已于 2026-08 从代码、契约、
  环境变量和文档中整体移除，注册仅保留邮箱验证码。
- 如未来需要恢复，应遵循此前的边界：不使用 Twilio Verify，必须取得大陆短信资质，
  不得接入宣称“免资质直发 `+86`”的境外或灰色通道，并同步恢复对应的 API 契约与测试。

### 防刷

- 当前 API 已执行请求来源检查、按 IP 限流和按目标限流。
- Cloudflare Turnstile 尚未创建或接入。
- Turnstile 必须在 API 服务端校验；浏览器组件通过不能单独作为放行依据。
- Turnstile 是现有限流的补充，不能替代发送冷却、目标限流、费用告警或服务端授权。

## 目标接入边界

消息模板、验证码生命周期和业务错误属于 API；服务商 SDK/HTTP 调用属于独立传输适配器。
Web 不得直接持有或调用邮件或 Turnstile 的服务端密钥。

```text
Web registration form
        │ same-origin API
        ▼
Fastify route ──> origin + Turnstile + rate limits
        │
        ▼
verification service ──> repository-owned template
        │
        └──> email transport adapter ──> Resend
```

传输层是可替换的适配器。当前实现了两条：HTTP API（`RESEND_API_KEY`，优先）与 SMTP
（`SMTP_*` 变量，回退）。两条路径用显式的提供商变量区分，同一份 Key 不会在两种语义下
被混用——2026-09-21 的生产事故（把 HTTP API Key 填进 `SMTP_PASSWORD` 导致 SMTP AUTH 535、
注册接口 500）正是混用的后果。更换传输方式时，验证码规则、模板、
限流和 HTTP 契约保持不变。

## DNS 与企业邮箱共存

- Resend 的 DKIM 与专用 `send` return-path 记录用于事务邮件，不承担人工收件箱功能。
- 企业邮箱通常在根域名配置收件 MX，可以与 `send` 子域的 Resend MX 共存。
- 一个主机名只能发布一套有效 SPF 策略；不要为同一主机名重复创建多个 SPF TXT 记录。
- 根域名只应有一条有效 DMARC 策略。当前先监测，提升到 `quarantine` 或 `reject` 前必须确认
  所有合法发信源均通过 SPF 或 DKIM 对齐。
- 更换权威 DNS、邮件服务商或企业邮箱前，应先导出现有记录，检查 DNSSEC，并设计可回滚
  的 TTL 与切换窗口。不要直接删除尚在使用的 DKIM 或 return-path 记录。

## 密钥与隐私规则

- API Key、Token、验证码、密码、恢复代码和证件材料不得进入 Git、文档、聊天、截图或日志。
- 生产密钥只存放在服务器密钥配置或受控密钥管理系统；本地副本放入密码管理器。
- 服务商凭据必须采用满足功能需要的最小权限，并尽可能限制到指定域名或发送用途。
- API 错误和日志不得输出验证码、Authorization Header、完整服务商响应或完整邮箱/手机号。
- 凭据泄漏时先撤销并轮换，再检查服务商发送日志、费用和异常目标；不要只修改应用配置。
